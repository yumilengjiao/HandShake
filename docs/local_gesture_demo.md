# 实验性本地手势演示播放器

**最小上层应用对接**：真实分类模型 → 原有手势策略/唯一调度器 → 本程序的幻灯片页码。

这是独立的、显式授权的实验入口，不改变 Flutter 的只读/影子协议。不是 PowerPoint、WPS、LibreOffice 的进程控制，不向操作系统注入按键，不承诺当前模型能可靠完成现场翻页。报告中的“未验收真实手势控制”仍成立。

## 启动

本机训练交付目录已接收，先做不打开相机的检查：

```bash
uv run --extra training handshake-demo \
  --run artifacts/runs/20261102T174832Z-tcn-af17e513 --verify-only
```

启动独立 OpenCV 演示窗口（不需要 Flutter）：

```bash
uv run --extra training --extra perception --extra demo handshake-demo \
  --run artifacts/runs/20261102T174832Z-tcn-af17e513 --allow-local-demo
```

选中的`--run`是你明确认可的本地交接目录，读取其中`export.json`和`calibration-receipt.json`，检查相对路径、模型完整性和校准绑定。它不修改`latest.json`，也不要求复制训练缓存。随包哈希不是独立的真实性认证。

需要已准备好的`artifacts/perception/hand_landmarker.task`，也可用`--perception-model PATH`指定。本次没有新下载相机模型。其他机器需按[感知说明](perception_diagnostics.md)准备可信资产。

Linux桌面已做“不打开相机”的窗口启动/绘制/退出检查；当前Wayland会话中的OpenCV会使用其可用的Qt平台后端，可能出现找不到wayland插件的提示。如果没有可用XWayland/显示服务，不把窗口启动当成功。尚未验收其他平台。

## 操作（键盘焦点在该窗口内）

1. **C**：明确打开相机。窗口启动本身不会开相机，不允许重复启动第二个worker。
2. **E**：启用本地手势会话。必须已有新鲜页面回执；模型忙时可稍后重试。
3. 一只手放在画面内保持中立；窗口显示`O available: True`后，按 **O** 明确选择控制手。
4. 继续保持中立，等待重新积累32帧窗口及400 ms释放期。更换owner不会沿用旧模型历史。
5. **TLT（向左抛动）**尝试上一页，**TRT（向右抛动）**尝试下一页。动作后回到中立；不是按住动作持续翻页。
6. **空格**：立即撤销手势控制，但保留相机预览。**Esc/Q/关闭窗口**：撤销控制、关闭相机并退出。

本地停止不是系统全局热键。阻塞的原生驱动/模型不能被声称已安全取消；2秒内没有确认释放会报错退出，不能启动另一个worker冒充恢复。

## 演示自己的PPT内容

先在PowerPoint/WPS等软件将幻灯片导出为`001.png、002.png、...`，放在一个目录，然后添加：

```bash
# 接到上面的启动命令后
--slides /path/to/numbered-slides
```

仅接受1～32张PNG/JPEG，按文件名排序；每张≤16 MiB、≤800万像素，禁止目录外符号链接和动图，缩放到960×540后在内存中展示。输入图片不会被改写，不解析PPT宏、PDF脚本或网络资源；没有原PPT的动画和音视频。这是内容导入，不是外部PPT控制。

## 保护与模型限制

- 模型、校准或来源标为合成，真实演示入口会拒绝；原合成诊断入口仍只供测试。
- 默认停止 → 明确启用 → 单手中立owner → 换代预热 → 释放 → 类别+几何证据 → 单次事件。保留0.8类别开启阈值、0.18位移、150 ms时效、100 ms采样间隔及冷却等既有参数，没有为展示强行放宽。
- 渲染/心跳失效、失跟、输入过期、异步模型结果迟到时不授权新动作。UI画图时发生owner换代/页码更新，旧回执只会被拒绝，等待新回执；固定超时仍生效。
- 页码变更只发生在专用`PresentationBackend`，目标固定为本机这份演示稿；无法替换为任意外部执行后端。
- 相机图像只在有限内存槽中处理，不录制、不上传、不保存。
- 当前TCN左/右类未拒识召回仅33.46%/46.49%；在T=1.5、0.8置信度下的**端点**召回更低（约9.15%/11.79%）。实际事件还须满足时序与几何条件，所以可能较难触发。不能用降低门槛来冒充模型已变好。

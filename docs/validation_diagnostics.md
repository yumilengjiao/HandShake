# 当前TCN诊断与指标改进计划

## 已核实的问题，而不是“调大一个参数就变好”

本次只读取交付的验证分数与训练日志，没有训练网络、读取测试样本或改变已交付模型。主报告仍采用全部99,909个有标签端点。

| 口径 | 全部标签准确率 | 接受样本准确率 | 覆盖率 | Macro-F1 | 左/右类Recall |
| --- | ---: | ---: | ---: | ---: | ---: |
| 原模型，不拒识 | 78.85% | 78.85% | 100% | 46.52% | 33.46% / 46.49% |
| T=1.5，拒识阈值0.6 | 65.99% | 90.23% | 73.14% | 37.09% | 22.43% / 31.52% |
| T=1.5，仅按策略0.8置信度过滤 | 54.80% | 94.94% | 57.72% | 23.43% | 9.15% / 11.79% |

- 拒识算作全部标签分母中的未识别，不能删除后宣称总体准确率提高到90%以上。
- 第三行**不是完整手势策略实验**，没有施加owner、预热、几何、持续时间、释放和冷却条件，也不是实际翻页成功率。
- 温度缩放不改善原始argmax类别判断；它改善的是概率/拒识的解释。
- 训练标签中NOG/P1F/P2F占85.76%，最大/最小类样本数约44.80倍；验证中前三类占85.40%。少数类Recall比总体Accuracy更值得关注。
- 训练损失从0.498降至0.229，但最后验证损失0.851，高于首轮0.732；最佳checkpoint是第2轮。继续增加epoch不是当前首选。
- ready子集准确率81.90%、Macro-F1 48.37%；not-ready子集准确率72.54%、Macro-F1 42.97%。两者类别组成不同，不能证明“只要过滤未就绪就能提高泛化”，更不能用81.90%替换主结果。

## 一个没有采用的快速“补救”

额外做了5个固定系数的验证集探索：用训练集类先验对logits作`z'_c = z_c - α log(p_train(c))`修正，没有修改神经网络权重。

| α | 验证Accuracy | 验证Macro-F1 |
| ---: | ---: | ---: |
| 0 | 78.85% | 46.52% |
| 0.25 | 77.71% | 46.88% |
| 0.5 | 76.05% | 46.61% |
| 0.75 | 72.25% | 43.83% |
| 1.0 | 68.90% | 41.64% |

**没有部署这个修正，也不把46.88%改写进主报告**：它是在同一验证集上的探索，只提高约0.36个百分点，却损失总体准确率与非手势召回，左右手势的Precision也下降；没有独立测试或置信区间证明有益。随意强行偏向少数类，并不能代替可靠训练。

## 推荐训练同学按顺序做的实验

1. **先跑MLP对照**，保持相同数据、特征和评估端点，检查TCN是否真的从时序中获益。当前未收到MLP正式结果。
2. **单变量降低学习率**：`1e-3 → 3e-4`，其余设置不动，观察验证Macro-F1及各类Recall，不只看loss。
3. **单变量增强权重衰减**：`1e-4 → 1e-3`，先保持学习率1e-3。只有明确看到有益方向后再组合，不进行无记录的大网格搜索。
4. **类别平衡损失/采样**是下一优先级，但当前训练器仅实现uniform sampling与普通masked CE，不能在配置中填一个不存在的`balanced`选项就宣称支持。实现时应从**训练标签**计算权重，可先试平方根逆频率，记录有效类别/零支持处理和权重归一化；不要同时叠加激进重采样与强加权。
5. 检查点击/双击的区间边界、窗口末端标签，以及没有手/多手帧的处理；再考虑按独立动作段统计事件指标。**不要**把相邻窗口随机分到train/val/test。
6. 短名单配置用相同的预先指定种子集合（如42/43/44）复验并报告均值/波动；不要试很多种子后只挑最好一个。
7. 模型、校准和交互策略冻结后才访问最终测试；每个新模型都要重新导出、重新校准，不能沿用旧模型的sidecar。

暂不建议直接加宽网络、增加很多卷积层、增加epoch、把`min_delta`改得很小只追微小波动，或者为了“能翻页”盲目降低线上门槛。特征维度、窗口或架构一旦改变，还必须同步包契约和重新导出，不能强行加载到现有模型包。

所有建议都只是待验证假设；本轮没有产生“调参后模型”的真实训练成绩。

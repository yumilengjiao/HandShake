## 新增：把短历史与质量/ready 问题分开

`diagnose --cache` 将已有分数归档与其**同一份紧凑 v3 验证缓存**关联，只读取 `valid_length` 等元数据，不重新前向、不加载权重、不导入 torch。核验数据/split/归一化/配置/词表、缓存索引及端点摘要，再逐批检查 label、class_valid、ready 和行数；两份输入的不可变 guard 持续生效。

三种子集互斥且穷尽主标签分母，主报告仍保持79.20% / 49.14%：

| 子集 | 有标签端点 | Accuracy | 固定15类 Macro-F1 |

完整历史不等于 ready，完整但未 ready 子集的类构成也不同，不能仅凭总体 Accuracy 认定质量不重要。各子集指标不能替代主指标或当作因果证明。

## 接下来优先做什么

1. **审查点击/双击的因果可辨识性。** 依据原始标注时间和可信轨迹，检查第二次点击前单击/双击是否共享可观测前缀，及有效运动阶段与标签区间是否对齐。缓存可见标签片段不是独立动作；不得把片段计数冒充动作数量。
2. **再做针对性的时序表示实验。** 候选是在相同94维特征、32帧因果窗口上引入多尺度历史汇聚/显式局部变化表达，与原 TCN 单独对照。现在只是候选，尚未实现或证明提分；不提前声称换网络能解决任务歧义。
3. **不删难样本、不偷看未来。** 保留短历史、未 ready、NOG和全部类别；不合并单击/双击或更换验证分母来抬分。若窗口/特征版本确需变化，应新建冻结缓存和同版本参考，不混接旧运行续训。
4. 新候选先限定一个变动及预算，再固定种子复验；模型/策略冻结前仍不运行真实 test。此次诊断代码更新会改变项目的训练实现摘要，旧 run 的严格 resume/重新导出可能拒绝；已导出包的读取与校验不受影响，应保留原包，不绕过身份校验。

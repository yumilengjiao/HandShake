# 原生多端架构与实施边界

> **2026-10-31增量**：[Flutter Linux合成原型与本机桥接](native_stack_decision.md)已构建/原生启动，作为T36/T20第一阶段。真实相机/模型/应用调度尚未接入；以下多端要求继续作为验收目标，不由原型自动满足。

> 当前需求基线：native-v2，替代此前“最终采用 Web”的界面形态约定。该架构修订时只改文档；后续T03/T04/T06已经增加采集/感知/标注代码，验证与原生SDK阻塞见 [实施记录](verification_t03_t04_t06.md)。原生产品界面、手机应用和真实应用控制尚未实现。

## 1. 产品目标与“跨平台”的含义

交付可安装、无需浏览器作为主入口的应用，优先覆盖 Windows、macOS、Linux，以及 Android、iOS/iPadOS。桌面先完成闭环，手机是明确的后续产品交付，不仅是一个遥控页面。其他系统（如 HarmonyOS）、无界面设备按同一适配协议评估；没有对应 SDK、运行时、硬件或分发条件时标为待评估/受限，不承诺所有操作系统无差别运行。

“原生”在本项目中指本地安装、通过受支持的系统 SDK 访问相机与生命周期；允许跨平台编译框架，不要求每个平台独立重写，也不以网页套壳或手机上运行桌面 Python 环境冒充适配完成。

必须分开报告三个层次：

1. **能安装和识别**：本机相机、关键点、自训模型、状态展示和启停。
2. **能操作本应用**：例如内置演示页/阅读视图；不需要跨应用输入权限。
3. **能控制外部应用/设备**：只通过获授权的应用接口、插件、系统能力或目标设备 Agent，按具体能力验收。

手机安装成功不等于能操纵任意 App；桌面安装成功也不等于全局键鼠控制可用。训练仍在电脑完成，手机只部署所需感知资产与推理模型。

## 2. 本机优先的逻辑架构

```text
原生界面（桌面窗口 / 手机触控界面）
  ├─ 用户指令 ───────────────────────────────┐
  └─ 状态快照、预览与结果 ◀─────────────────┤
                                            ▼
平台相机适配 → 标准帧 → 感知适配 → 标准关键点观测
                                    ↓
                    质量/轨迹 → 共享特征/时序窗口
                                    ↓
                          自训模型推理适配器
                                    ↓
                     交互状态机与安全命令调度器
                                    ↓
             ┌──────────────────────┼──────────────────────┐
             ▼                      ▼                      ▼
       本应用内适配器         系统/外部应用适配器     可选远程适配器
       内置翻页等             仅获授权的能力         配对后的目标 Agent
```

独立停止与健康监控不等待 UI 绘制或模型返回。默认 dry-run，用户启用后仍需唤醒和控制权；不因换系统而削减旧 epoch 拒绝、去重、失跟停止与释放要求。

**逻辑分层不要求拆成多个服务。** 桌面可先用 Python 核心与原生 UI 在本机直接调用；若 UI 技术栈不同，采用受控本机 IPC/FFI。手机独立模式必须在本机完成识别和安全决策，不强制联网或启动电脑。远程模式是单独的可选能力，不能替代手机独立模式验收。

## 3. 技术选型与复用策略

T36 在 T20 正式锁定 UI 前完成有时间上限的选型验证，先比较以下路线，不在文档中宣称某个框架已经支持全部插件：

| 候选 | 优点/需要验证的代价 |
| --- | --- |
| Flutter 等原生编译多端 UI + 平台插件 | 可共享界面；必须实测各目标的相机、感知桥接、模型运行时、桌面核心通信与安装包 |
| Qt 桌面 UI + Android/iOS 原生壳 | 可先复用 Python 桌面核心；移动壳、协议绑定与便携核心需单独实现，不把 PySide 打包等同于手机支持 |

决策比较开发成本、许可证、无障碍、相机帧通路、后台生命周期、离线资产、原生插件、运行时算子与分发条件。选定一个主路线并记录否决/降级理由，不同时维护多个试验 UI 为正式产品。移动工具链不可得时记录阻塞项和补测责任，不能伪造实测；桌面可在保留接口的条件下继续。

- Python 保留为训练、评估和桌面参考实现；现有 `handshake-core` 不因需求变更直接删除或改成手机安装包。
- `CameraSource`、`PerceptionAdapter`、`Predictor`、`ActionBackend`、生命周期/权限适配器隔离平台 SDK；UI 不拥有真实操作权限。
- Python 训练与在线特征复用 `shared/` 同一实现。移动运行时优先复用可绑定的公共核心；必须移植时以单一版本化规范和 golden fixtures 验证特征、窗口、ready、logits、事件、停止语义，不允许各端自由复制并修改算法。
- 公共协议与绑定不等于跨语言直接导入 Python。跨进程/语言载荷须有 schema、严格整数时间编码、错误枚举与兼容性握手；新增字段先升版本，不能在本次文档修改中假装已修改现有 schema。
- MediaPipe 的桌面 Python、Android、iOS 接口分别核验输出、时间戳、坐标、模型资产和回调行为。框架可构建不代表相机/感知插件可用。
- T16 保留桌面 PyTorch 参考输出；T37 按目标实测 ONNX Runtime Mobile、LiteRT、Core ML 等候选之一。不是要求全部转换，更不能把 `.pt` 直接视为手机可执行模型。模型转换/量化重新验证校准、拒识、事件与性能。

## 4. 平台能力边界

| 平台族 | 原生本机目标 | 外部控制边界 |
| --- | --- | --- |
| Windows | 安装、相机、识别、内置应用 | 核验权限等级、DPI、焦点与独立停止后启用白名单适配器 |
| macOS | 安装、相机、识别、内置应用 | 相机/辅助功能等权限分开申请；签名、公证与目标应用权限实测 |
| Linux X11 / Wayland | 分别验证发行版、显示会话、相机与安装 | X11 与 Wayland 不共享“已支持”结论；Wayland 优先受支持 portal/应用 API，不绕过保护 |
| Android | 本机相机、离线推理、触控启停、内置应用 | 应用接口优先；无障碍等敏感能力仅在适用场景、明确授权和合规条件下单独评估，不是通用注入后门 |
| iOS / iPadOS | 本机相机、离线推理、触控启停、内置应用 | 普通 App 不能任意向其他 App 注入触摸；只评估目标公开接口/系统允许的集成，不把此能力列为必达 |
| 其他 OS / 无界面设备 | 评估 SDK、相机、推理运行时、CPU 架构 | 缺 UI 可用受控 CLI/服务接入；不假设有 Python、Android 兼容层或全局输入能力 |

这是**目标矩阵，不是支持声明**。实际状态见 [平台支持记录](platform_support.md)，每个平台按“安装 / 相机 / 本地识别 / 应用内控制 / 外部控制 / 安全 / 分发”分别填未验证、通过或受限及证据。

## 5. 相机、生命周期与时间

- 平台适配器把 YUV/BGRA/BGR 等输入转换到协议要求的 RGB；记录旋转、裁剪、宽高、镜像与前后摄像头。预览镜像不能暗改词元方向。
- 记录源帧时间与 timebase，最新帧队列有界。无可信曝光时间时标明软件采集近似；不把回调完成时间当曝光时间。
- 手机进入后台、锁屏、相机中断/权限撤销、系统回收资源时默认停用、清候选并释放；恢复只预览，需要重新启用/唤醒。桌面普通失焦与系统休眠区分，允许演示软件前台时仍控制，但需目标策略与独立停止。
- 不承诺所有手机都能持续后台开相机，也不依赖退出回调必达或进程被杀后还能执行 finally。无可靠释放保证时禁用持有类外部控制。
- 手机安全验收增加横竖屏、相机切换、热降频、电量/内存压力、长时间运行；不能仅用桌面 FPS 或模拟器代表手机可用。

## 6. 可选手机控制电脑（T38）

```text
手机原生 App（相机 + 本地识别）
  → 加密认证通道（版本化标准命令，不传任意脚本）
  → 电脑 Agent（本地确认、能力/目标/期限校验、独立 watchdog）
  → 已支持应用
```

本机独立模式不要求网络。远程模式优先局域网，需双端确认配对、撤销凭据、控制会话租约、重放防护、有界队列和限速；默认不传原始视频，不直接公开控制端口到互联网。

两台设备的单调时钟不能直接相减或比较绝对 TTL。协议分别记录源时间、接收时间、序号、会话代际和可验证的新鲜度界限；如估计时钟偏移要记录不确定度与漂移，超过预算拒绝。单纯收到消息后重启 TTL 不能证明手势新鲜。

断连、手机后台或租约过期由**执行端本地 watchdog** 停止并释放；不能只等手机发 stop。重新连接换会话/stream，人工重新授权，不补发旧动作，翻页等非幂等操作不自动重试；不确定回执明确显示。

## 7. 阶段与验收责任

| 阶段 | 任务 | 退出条件 |
| --- | --- | --- |
| 课程 P0 / 桌面首版 | T01～T24 核心项、T28～T30；T36 早期选型 | 一个实测桌面系统原生闭环、安全与实验完成；兼容边界可解释 |

| 可选 P2 / 跨设备控制 | T38 | 配对手机控制电脑及断连安全，不代替 T37 本机验收 |
| 后续平台 | 按 T36/T37 模板增补 profile | 对新 OS/架构重新验证插件、运行时、权限与分发，不继承同名平台的全部能力 |

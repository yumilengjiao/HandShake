最新需求改为原生安装应用，尽量覆盖电脑和手机，不以浏览器为主入口。桌面先交付，Android/iOS 本机识别和应用内控制是明确的后续产品目标；其他 OS 按能力评估。课程算法、数据和安全要求不变。现有交付仍只有 Python 核心、离线 CLI、契约、配置、标注草案和合成验证；本次只更新文档，不改源码、依赖或历史证据。详见 [原生架构](native_architecture.md)。

“手机支持”分为原生安装、本机相机/识别、本应用内控制、受授权外部控制四层。前后摄像头、横竖屏、触控停止、离线资产、后台/锁屏与权限撤销须真机验收。Android/iOS 的外部应用控制受系统沙箱限制，不默认拥有全局键鼠或触摸注入权限；无法提供的能力显示受限。T38 手机控制电脑为额外选项，不代替 T37 本机运行。

## 平台与安全决策

- 当前实测宿主见 [平台支持记录](platform_support.md)；只验证 mock，不具备演示设备认证。
- 最大检测手数 2，控制手数 1。启动默认 `dry_run` 且未启用；合成演示中的启用/owner 是显式脚本前提。
- 初始白名单仅 `previous_slide` / `next_slide`，能力枚举另含 media/volume/pointer/scroll；枚举存在不表示后端已经实现。
- 真实控制要经唯一调度器，核验 stream/epoch、新鲜度、owner、能力和明确目标；UI 不能直接修改内部状态。
- 当前 `live` 拒绝启动。独立停止不依赖手势模型；Wayland 全局按键、焦点与权限未验证前，不承诺桌面注入。未来优先验证明确对象的应用内翻页目标，必要时再选择已支持的宿主方案。
- 原生进程挂起、手机后台/锁屏、相机中断、权限撤销的停止/释放归 T20/T24/T37；可选远程断线安全归 T38，执行端必须有本地 watchdog。不能依赖退出回调必达，当前尚无原生壳或网络服务。

## 评价口径 v1（测试前登记）

| 项目 | 固定口径 | 研究目标/当前实测 |
| --- | --- | --- |
| 分类 | 按用户固定 split；混淆矩阵、每类 P/R、Macro-F1、Balanced Accuracy | 争取 Macro-F1 ≥0.90；当前无模型结果 |
| 事件 | 同类型一对一；参考时刻前 100ms 至后 500ms；额外事件计重复/错误；唤醒、退出、翻页分别统计 | 争取事件 F1 ≥0.90；未实测 |
| 自然误触 | 背景区间由协议/真值预定义，不按 ACTIVE/ready 裁剪；报告误触次数、小时数、不可用时长及召回 | 研究目标 ≤1次/小时；约20分钟测试背景不足以可靠证明 |
| 事件层次 | 拟提交、确认注入、应用响应分别统计 | mock 的 not_attempted 不计实机成功 |
| 确认时刻 | 静态从可见稳定起点加保持时长；动态首个满足位移与时长的帧 | [手势协议](gesture_protocol.md)，全部起点为 draft |
| 性能 | 源帧→感知→推理→事件→注入→应用响应；固定设备/分辨率/帧率/手数；报告 p50/p95 | 新鲜帧→注入 p95 争取≤150ms；参考确认→注入≤450ms；未实测 |
| 停止/稳定性 | 故障注入分别测停止接收、禁新提交和释放完成；30～60分钟稳定性与长自然流分开 | 安全释放争取≤200ms；未实测 |

事件评估优先按时间排序匹配；多个预测/真值满足窗口时采用最大匹配数、最小绝对时间偏差的确定性匹配，平局按时间/ID 排序。T15 实现时需为该口径补测试，最终测试不能反向调参。保持时间、释放阈值与匹配窗口的更改都要升协议/评估版本并留原因。

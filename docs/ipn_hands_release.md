# IPN HandS 图片帧关键点：项目审查版本

版本：`ipn-hands-frames-v1`。这里只下载**逐帧图片对应的关键点与标签**，不下载视频、不执行包内抽帧脚本，也不需要重新运行MediaPipe。MLP/TCN输入仍是共享94维特征；动态手势保留图片帧顺序。

## 为什么现在可以采用这个版本

之前的阻塞是真实的：作者README公布的标注ZIP SHA以 `4686a2eb` 开头，而官方链接多次返回的文件以 `520dfbf3` 开头。**发布方旧SHA仍不匹配，原因尚未被作者确认**，本项目没有把它改写成“作者校验通过”。

在用户允许重新整理训练来源后，本次执行了实际内容审查，并冻结一个明确的**项目审查快照**：

1. 重新获取作者Git仓库，确认版本仍是 `093729579be671df0cc9dd8cbc58b9a342663800`；该固定README直接链接这两个公开数据文件，许可为CC BY 4.0。
2. 标注包82,274字节、206个成员CRC通过；逐成员记录大小/SHA。15类表、每个序列的连续区间覆盖、1-based含末帧边界及200个帧计数均通过严格解析。
3. **实际下载**375,332,617字节的MPHands关键点包（约357.9MiB）；它与作者公布的 SHA `e511bb2b…ce598` 一致。
4. 实际逐帧审查全部200个JSON、**801,476帧**：文件清单、图片帧名、数量、21点xyz、有限数值、0～2手及标签时间轴均一致，没有缺失帧或混用旧时间轴。
5. 200个序列的148/52官方train/test归属，与固定Git版本的 `annotation_ipnGesture/ipnall.json` 独立对照一致；**没有使用原版时间标签替换HandS标签**。
6. 原版标注链接实际上是公开文件夹，并非ZIP文件。找到其中的 `metadata.csv` 后，核对了全部200个来源名称、官方集合归属及旧版本帧数。CSV不含受试者ID，未将其伪装为身份映射。

审查清单是包内 [`shared/defaults/ipn_hands_release.json`](../shared/defaults/ipn_hands_release.json)，由 `data/sources.json` 中的ID与SHA固定。它记录两个包的发布方SHA、项目采纳SHA、标注逐成员清单、独立来源哈希、帧统计和来源采集组。

运行时只有这个**明确审查的精确版本**能使用例外标注SHA；没有 `skip-verify`，没有“下载后现场计算并自动信任”。去掉项目review引用后仍按发布方旧SHA校验并拒绝该标注包；未来任意字节变化、伪造review、不同来源版本均拒绝。

这项决定依据官方发布链路与完整结构/关联审查，**不声称获得作者的SHA更正、人工逐帧语义复标或密码学签名**。原始公布值与差异永久保留在来源清单中。

## 固定划分，不再让使用者编造主体表

默认把同一来源采集键（移除末尾 `_#序列号`）的四个完整序列放在同一组，共50组。此键只是**来源采集组**，不是独立核实的参与者身份。

- 保持官方test的13组/52个序列不变。
- 在官方train的37组中，按 `sha256(release_id + '/' + capture_group_id)` 排序，预先选前8组作val；不按模型分数或测试集成绩挑选。
- 最终为 **116个训练序列、32个验证序列、52个测试序列**。
- 图片帧不会随机跨集合，四个同组序列不会分散到不同集合；不同源序列和track之间不会拼窗口。
- 导入、缓存、训练manifest及评估报告都记录 `grouping.unit=source_capture_group`、`subject_identity_verified=false`。

既有记录格式的 `subject_id` 字段为兼容保留，但默认值使用明确的 `capture-group:` 命名空间，其含义是分组键，**不能写进报告冒充真实主体ID或已认证的跨人评估**。可以报告“固定来源采集组留出”；如果课程要求独立的跨被试验证，仍须另取可靠身份映射。

需要自己提供真实主体计划时，在配置中设置 `split_mode="reviewed_subjects"`，继续使用原来的严格 `subject-plan-v1` 和真实审核引用。默认使用者不需要填写假的 `review_reference`。

## 数据可用性与质量范围

审查的全部帧中：

| 估计手数 | 帧数 | 训练处理 |
| --- | ---: | --- |
| 0 | 182,516 | 保留无手时间轴，不伪造关键点/类别监督 |
| 1 | 608,095 | 使用原始来源类别，保留几何质量与窗口就绪标记 |
| 2 | 10,865 | 不猜哪只手是操作者，类别监督置为不可用 |

数据的NOG、P1F、P2F类别占比较高，应报告每类指标和Macro-F1，而不是只报总准确率。未进行基于模型成绩的删样本、伪造图片、重复静态图片或补帧。MediaPipe原始预测错误和几何不合格观测不等于人工修正真值；此来源也不提供应用操作意图和真实终端响应真值。

## 使用

```bash
uv run download
uv run prepare
uv run train --dry-run
# 在允许训练的机器上：
uv run train
```

`prepare`从本版本自动生成采集组计划、完成导入、构建train/val/test紧凑缓存，并发布完整回执。首次处理80万帧需要时间和磁盘空间，命令会显示进度；不需要视频、摄像头、Flutter或人工逐行编辑标签。

本机已经实际完成上述下载、全量导入、三侧缓存和训练预检；重复download/prepare也通过校验并复用现有产物。汇总见[机器可读证据](verification/ipn_hands_preparation.json)：

| 缓存 | 已表示端点 | 有标签监督端点 | ready覆盖率（非准确率） |
| --- | ---: | ---: | ---: |
| train | 459,704 | 334,604 | 48.31% |
| val | 131,189 | 99,909 | 53.03% |
| test | 213,777 | 保留作最终评估 | 62.60% |

train/val的15类均有监督样本。另用真实缓存的4个就绪端点检查未训练MLP/TCN前向，输入32×94、输出15类且数值有限；没有优化器、反向传播或正式训练成绩。真实统计只有局部腕点原点xyz三个恒零维度使用std回退，符合以腕点为局部原点的特征定义。

`uv run check` 的828项非训练回归通过（4项明确deselect，训练/梯度文件另行排除）；新测试覆盖发布方旧SHA保留、坏review拒绝、逐成员校验、固定分组、无手填计划准备及评估范围保留。Windows/macOS和训练硬件仍以实际CI/目标机结果为准。

软件回归使用合成小样例，不能代替上述真实数据准备证据。本机未运行神经网络训练、相机或外部应用控制；准备通过也不代表模型已达到识别指标。

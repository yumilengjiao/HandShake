# data：数据集与数据版本

> 这是项目专用的数据集目录，与算法代码分开。当前只有本说明，没有参与者数据、视频、关键点、标签或已冻结的数据划分。

## 主责与任务

- **A 管理数据版本、划分和校验；A+B 共同采集、标注和复核；B 负责采集工具。**
- 对应 T05～T11，以及 T26/T27 的新增数据与适配清单。
- 详细协议见 [任务导航](../task_plans/README.md) 和总方案第 13 节。

## 后续存储布局

以下子目录按实际采集需要创建，目前不放空数据文件。

```text
data/
├── README.md
├── manifests/             # 授权范围、录制账本、版本、血缘、哈希与完整性
│   └── prompts/           # 提示时间/取消/练习标记；仅供标注参考
├── raw/                   # 获得单独授权后保存的原始视频
├── landmarks/             # 帧表、关键点、源时间、轨迹、质量/处理状态
├── context/               # 人工启停、模式、健康与上下文事件
├── annotations/           # 类别、意图、阶段、独立事件真值与标注版本
├── splits/                # 按用户/会话固定的 train/val/test 清单
├── features/              # 可重建的特征/窗口缓存
├── external/              # 经许可导入的公共数据及来源说明
├── personalization/       # 明确授权的 support/query 清单和样本
└── reports/               # 数据完整性、分布、标注与泄漏检查报告
```

pilot/main/新增版本通过 manifest 的数据用途、dataset_version 和源 ID 区分，不随意复制同一用户到不同集合。原始内容只读，修订标签/特征生成新版本。

## 数据流

```text
backend 授权采集
  → 原始观测与上下文
  → A/B 标注复核
  → 预登记用户划分固化
  → shared 公共特征处理
  → algorithm 训练/评估
  → artifacts 模型及实验结果
```

- 相同 recording 的观测、上下文、提示、可选视频必须能按相对时间对齐。
- 帧表区分成功无手、未处理和感知失败，不能丢掉无手时间。
- 人工事件真值独立于检测是否成功；模型漏检不能导致真值被删除。
- 提示和真值不输入在线模型，不在回放中替模型授予控制权。
- 统计只在训练集拟合，先划分后滑窗；测试失败资料不偷偷回收训练。

## 初期采集规模

课程计划起点为 8 人、4 个词元、每类每会话 10 次、2 会话，约 640 次正例尝试；每人每会话约 5 分钟自然活动，共约 80 分钟背景。**这是计划，不是已有数据。**

以真实授权、参与者和完整性为准，记录有效、失败和取消数量；研究扩容不作为课程前置。补采连续唤醒—操作—回程—释放—自然活动脚本，不只录孤立手势。

## Git 与双方共享规则

- 根 `.gitignore` 默认忽略本目录除 README 外的一切内容，包括真实标签和划分清单；这样可以先保留目录，而不误公开数据。
- 两人通过经授权的受控存储传递数据，核对版本、文件哈希、授权范围与完整性；不能认为 `git pull` 会自动同步数据。
- 若以后采用 DVC/Git LFS 或发布匿名清单，先复核许可、隐私和存储规则，再显式调整忽略配置，不直接强制加入真实文件。
- 授权原件、真实姓名映射、实名课程资料和个人档案放根本地 `private/`，不放公开文档。
- `.gitignore` 不是加密或权限控制；本地访问、备份、保留期限和删除仍需管理。

## 不应放在这里

- Dataset/增强/特征源码：分别放 `algorithm/` 或 `shared/`。
- 训练权重、优化器状态、事件日志和最终模型评估：放 `artifacts/`。
- 纯合成、可公开的小型测试样例：放 `tests/fixtures/`。
- 可公开的数据集说明与脱敏统计：放 `docs/`，不把真实清单直接复制过去。

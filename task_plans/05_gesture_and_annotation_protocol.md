## 目标

在正式采集前定义“什么动作是什么类、何时可确认、何时释放、什么是自然动作”。类别标签与设备命令分离，避免“同一图像因为想不想翻页就被标成不同类别”。

## 首版词表与编号

| id | 词元 | 可见动作定义 | 事件语义 |
| --- | --- | --- | --- |
| 0 | no_action | 清晰可见且不属于词表，或普通背景；感知缺失另带质量掩码 | 不执行 |
| 1 | wake_open | 张掌稳定保持的候选姿态，具体形状由试采集示例冻结 | 请求控制权，需 UI 已启用 |
| 2 | swipe_left | 掌心沿模型输入图像 x 减小方向完成明确横向挥动 | 当前模式映射为上一页/上一首等 |
| 3 | swipe_right | 掌心沿模型输入图像 x 增大方向横向挥动 | 当前模式映射为下一页/下一首等 |
| 4 | exit_pose | 先试用握拳保持，与其余词元可区分后冻结 | 辅助退出；不承担唯一紧急停止 |

这里的左/右指未镜像模型坐标，不自动等于使用者自身左右；用原图与预览的箭头示例教学，并通过映射配置满足用户习惯。以后增加 point/pinch/media_toggle/volume_pose 必须追加版本、补采数据和重训，不复用旧 id 改含义。

## 标注与采集协议

1. 编写每类正例、近似负例、易混淆与不确定案例。先给 0.5～1 秒动作前后背景的试采集起点；慢动作或静态保持可延长，不把统一片长变成类别提示。
2. 时间区间使用 `[start_ns,end_ns)`，同轨迹类别区间不重叠；准备/有效/释放阶段另存。阶段头选做也保留原始边界，以免后续重录。
3. 静态姿态：首次满足规定保持时长的时刻作为参考确认时刻；动态挥动：达到事先定义的方向/位移证据时刻。试采集后冻结可操作规则与标注图例，不用模型预测定义真值。
4. 分类监督首版只对动作有效区间赋对应词元，背景与已回到中性位置的过渡赋 no_action；无法判定的准备/释放区域 class_valid=false。阶段标签独立。词元相同的自然动作使用相同类别。
5. `intent_label=1` 仅指明确约定的操作请求；自然交流挥手即使类别为 swipe_left，意图仍为 0。`ambiguous` 对相应任务屏蔽损失，不能全部塞进 no_action。
6. 连续评估另记录目标命令和 reference_event_time；自然动作即使类别可判定也没有目标设备事件。静态唤醒/退出与普通翻页事件分别计分，不能混作一个事件全集。
7. 规定释放证据：回到中性区域并保持/明确张开等；单纯置信度下降或冷却结束不算完成新动作。界面/键盘启停与模式日志也要标注。

## 目标

证明通用适配层可以增加新目标应用而不改识别器。一次仅选一个明确软件和一个低风险功能，例如 PDF 阅读器的上一页/下一页；浏览器阅读、播放器专用功能等后续各按同样模板另立任务，不在一次任务内承诺所有软件。

## 实施步骤

1. 冻结目标应用、系统、版本、窗口/文档身份、操作范围与是否有受支持接口。优先可定位文档对象的插件/API，若只能系统输入必须明确焦点保护和权限限制。
2. 若功能等价翻页，复用 next_slide/previous_slide 的语义是否合适先评审；必要时定义 next_page/previous_page 新标准命令，并更新动作 schema、capability、ActionResult 与 UI，不能偷偷复用名字却改变参数含义。
3. 增加独立 mode/profile，将现有 swipe 词元映射新命令；物理词元不变无需重训。若新增动作词元，则走 T05/T07/数据补采与模型版本流程，不能只加映射文件。
4. 新 Backend 只接受已校验标准参数，实现 capabilities/execute/release_all 和权限/目标不存在/焦点不符/超时/不确定回执；不允许将模型字符串拼接 shell 命令。
5. 先 MockBackend 检查映射和能力，再人工直接命令实测应用，再模型 dry-run，最后受控 live。用带页码/状态标记的样例检查应用真实变化，边界页码和不支持命令单独测试。
6. 切模式增加 context_epoch、清旧候选/队列；阅读器失焦或关闭不得让旧命令落到其他应用。平台无法确认上下文时保守禁用或改用明确对象接口。
7. 更新支持矩阵、界面模式列表、使用说明和故障回归；不会因新增插件破坏默认演示/音乐/光标后端。

## 输出与验收

目标应用 profile、独立后端模块、能力与命令 schema 更新、授权样例文档、实机记录与 `docs/<application>_usage.md`。

- [ ] 复用识别与事件链路，新增实现局限于经过评审的命令/映射/后端。
- [ ] 目标应用状态变化可观察，系统注入与应用确认级别分别记录。
- [ ] 不支持能力清楚报错，关闭/失焦/切模式/stop 不误投递和补发旧命令。
- [ ] 只声明实际验证版本与环境支持，未验证软件不列“通用支持”。

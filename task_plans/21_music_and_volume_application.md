## 目标与进入条件

复用稳定主链路加入音乐模式，而不是建立另一套识别循环。课程仍以翻页为必做；本任务在 T23 主闭环稳定后实施。上一首/下一首可复用左右挥动，播放暂停和音量姿态不能凭空从五类旧模型中推断。

## 功能映射与接口

| 功能 | 实施路径 |
| --- | --- |
| 上/下一首 | mode=music，swipe_left/right 映射为 media_previous/next，方向可配置 |
| 播放/暂停 | 新的 media_toggle 姿态经 T05/T07 验证、补采并重训；早期 UI 按钮只算人工后端测试 |
| 音量 | 显式进入音量子模式后使用调节姿态和相对位移，非音量模式绝不累计 |

后端实现 media_play_pause/media_previous/media_next/adjust_volume；支持集与可查询信息逐项列明。Linux 可评估 MPRIS；其他系统采用实测受支持媒体接口，不能依靠未经验证的跨平台快捷键假设。

## 实施步骤

1. 选择一个明确播放器，记录接口、实例选择、权限、歌曲列表/状态查询能力；多播放器同时运行时要求明确目标或保守禁用，不能随机控制一个。
2. 对每个标准命令先用人工按钮验证，再接同一 T17/T18 状态机和调度器。播放暂停是非幂等切换，超时/回执不明时不能自动重试。
3. 扩充词表、标注、数据、schema/类表与模型版本；补充新词元对唤醒/退出的混淆实验。旧模型缺少词元时 UI 明确不提供该手势能力。
4. 音量采用速度控制：`rate=gain*signed_displacement_outside_deadzone`，`value=clamp(value+rate*dt,min,max)`。固定中性点、死区、最大每秒速率与发送频率，在验证/开发会话选择参数。
5. 只有离散音量步进的后端维护小数累计，量化发送有限步；失跟、离开子模式、停止时清空，不能恢复后补发旧变化。无法查询实际音量时只显示“增/减”，不显示猜测百分比。
6. 切换音乐/演示模式清候选并更新 context_epoch，同一挥动不能同时翻页和切歌。所有失败、拒绝与执行结果使用通用日志。

## 输出与验收

媒体后端、播放器支持矩阵、动作映射、必要新模型/数据版本、`docs/media_usage.md` 与音乐场景测试记录。

- [ ] 相同左右挥动在演示/音乐分别只触发一个正确目标命令。
- [ ] 切歌一次动作一次事件；播放暂停不因重复投递二次切换。
- [ ] 约束音量边界、实际时间积分、失跟停止；10/20/30Hz 下相似轨迹速率基本一致，注明容差。
- [ ] 无播放器、多实例、权限不足、状态未知、停止和模式切换均有清楚反馈。

MPRIS 实现前核对 [官方接口规范](https://specifications.freedesktop.org/mpris-spec/latest/)，具体方法签名和客户端兼容性在实机选择时冻结。

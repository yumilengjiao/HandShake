## 目标与前提

在明确用户主动选择匿名档案的前提下改善个人动作差异，不能用手部关键点做可靠身份认证。几何校准可在 T22 提前独立完成；本任务完整学习适配需 T25 的有效嵌入和独立会话数据。

## 分步实施

1. 档案先存惯用手、镜像/方向偏好、舒适映射区域、捏合开闭距离、滤波/确认时长、模型/schema版本与创建时间；真实姓名不必进入档案 ID。
2. 几何向导：静止数秒测抖动→画舒适范围→若干开闭捏合→少量动作→dry-run 验证。次数与持续时间以试用反馈调整，不称“无需训练即可适配所有用户”。
3. 原型方案：冻结通过验证的编码器，按每类 k=1/3/5/10 的 support 算均值原型；L2 距离/余弦及与通用分类头融合权重由开发新用户选择，不用当前查询集选择。
4. 若嵌入度量不足，可在训练用户上加入监督对比/episodic 目标并独立验证；明确训练损失、原型空间和归一化。不要对任意中间层直接宣称“少样本有效”。
5. 备选仅微调小分类头/适配层，冻结骨干，低学习率、有限步数/早停规则与通用样本约束均从开发用户确定；小样本没有单独验证时预定固定步数，不看查询成绩早停。
6. 新用户 support 与 query 至少跨会话，尽量跨日期；query 不进优化、阈值选择或 checkpoint 选择。测试用户适配后的结果单列，不再称零样本跨用户结果。
7. 自动高置信预测不当真值在线自训练；仅用户确认的样本可进入。新适配器先回放/dry-run，失败或版本不符回退通用包，保留备份和删除入口。

## 实验与输出

比较通用模型、仅几何校准、原型、可选小头微调。每 k 报每用户 Macro-F1/事件指标/校准时间/负向变化与区间；即使均值改善也披露恶化用户。为保证 k=10 有数据，应提前计划每类至少足够 support 以及独立 query，不能拿同一动作的多个窗口充当多次独立 support。

输出 `personalization/` 模块、profile schema、向导、support/query manifest、适配配置/权重和回退/删除说明。

## 验收

- [ ] 同一个录制/动作不会同时做 support 和 query；查询集不选参数。
- [ ] 旧档案版本不符禁用适配但仍可回退通用模型。
- [ ] 个性化不会改变紧急停止和白名单，安全测试按 T24 复跑受影响项。
- [ ] 数据不足或无稳定收益时仅交付几何校准并保留负结果。

## 冻结与执行顺序

1. 实验登记在开发期先起草：研究问题、数据/标签/split、预算、种子、匹配协议和主要指标。最终按顺序执行：验证连续流有限搜索各模型的校准/事件参数 → 生成不可变 frozen release candidate 及哈希 → 重跑受影响的 T23/T24 回归 → 冻结测试入口 → 运行最终留出测试。验证搜索包含类别 on/off、保持/释放/冷却，不在测试后再选最漂亮门限。
2. 课程必测：MLP vs TCN 分类、相同事件逻辑和可比调参预算下的事件 P/R/F1、重复触发、激活后自然活动误触与协议时长、实际 ACTIVE/不可用时长、目标 CPU 延迟、安全用例和失败案例。按 T15 分开拟提交/确认注入/应用响应结果；启动未就绪、漏跟、唤醒失败导致的漏命令仍计 FN，不能只在成功识别片段计算端到端召回。
3. 研究按单变量逐步比较：原始/局部特征、局部/局部全局、单任务/意图/阶段、拒识、基础/完整安全门控、增强、滤波、个性化与候选模型。移除安全门控只在离线/dry-run，不真实注入。
4. 每个方法保留同一用户划分与可比训练预算，报告参数/计算量/推理与后处理成本。研究主模型至少 3 种子，课程记录实际次数；按用户/会话统计，不把窗口当独立受试者。只有 2 位测试用户时以逐用户原始数值和范围为主，bootstrap/显著性结论极不稳定，不能仅靠重采样次数多就声称泛化显著。
5. 用户任务按实际实现选翻页、点击、媒体、自然动作干扰和停止。研究版可招约10～15人，课程如人数更少如实报告；方法顺序随机化/平衡，尽量控制学习效应和疲劳。
6. 错误按感知失效、词元混淆、意图误判、释放/重复、控制权、模式/焦点、后端执行分类。每类提供脱敏片段、源日志、原因与已修/未修状态，不只展示成功案例。
7. 最终测试后不得继续调参并沿用“未见测试”成绩；发现缺陷可修复后形成新版本并明确旧集已成为开发资料，额外测试材料另行留出。

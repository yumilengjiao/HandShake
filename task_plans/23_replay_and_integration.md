## 目标

建立同一输入可复现的“观测→特征→模型→事件→通用命令→后端→UI/日志”链路。先 mock/dry-run 后受控 live；后续音乐/光标接入时复用该入口，不复制流程。

## 实施步骤

1. 应用控制器负责输入源、轨迹/特征状态、predictor、interaction engine、mapper、dispatcher、UI snapshot 和 telemetry 的生命周期；各模块共享同一版本上下文。
2. ReplayClock 按录制时间和稳定事件序推进，合并输入、已记录人工上下文、健康通知与定时器期限；长无帧间隙仍在超时截止点触发挂起，不能等下一帧才执行。倍速/逐帧只影响观看；预测和真值提示不能替代人工启用日志或用于自动授予 owner。
3. 区分两种回放：逻辑回放固定假设推理即时完成，用于模型/状态机可复现对照；调度回放使用录制/模拟的提交、完成、丢帧与超时序列，用于验证乱序、新鲜度及竞态。只有源帧时间无法还原真实负载，不声称逻辑回放重现了在线所有故障。二者均使用虚拟时间而非当前墙钟，后端固定 mock/dry-run。
4. 录制模型包、特征 schema、配置、数据与代码哈希；输出预测摘要、状态转移、GestureEvent、ActionCommand、ActionResult 和时间分解。不能只保存最终“成功/失败”文字。
5. 建固定 regression fixtures：正常左右挥动及反向回程、保持/释放、自然挥手、无手、未处理帧、遮挡、多人冲突、失焦、乱序预测。来自训练/专用开发或纯合成资料，不把最终测试失败反复作为开发回归又称未见测试。
6. 同一模型/配置/fixture 的规范化事件列表一致：比较源时间、类型、上下文和原因，随机 UUID/运行耗时从一致性断言中剥离，或注入确定性 ID 生成器。对比 MLP/TCN 固定事件逻辑及验证搜索预算；参数可按各自校准结果配置并公开。更改门限/特征保留旧日志并输出差异。
7. 集成分三步退出：A 合成预测贯通 UI/mock；B 真实关键点回放＋自训模型 dry-run；C 在 T17/T18/T19 局部安全检查通过后，受控 live 完成有页码的脚本。

## 原生多端复用验收

P0 先验证本机原生桌面链路，不要求网络服务。T37 的移动核心复用同一逻辑/调度回放规范，逐平台比较特征、ready、事件和停止轨迹；跨语言时间编码需无损，UI 生命周期事件需录制/注入。授权手机实机资料单列，不能用相同 fixture 的数值一致性替代感知/帧率/热降频评估。

T37/T38 在各自集成时调用本任务已有方案补平台证据，不把其完整实现反设为 T23 桌面交付的前置。远程模式额外验证配对、乱序/新鲜度和执行端断连停止，本地模式断网仍可工作。

## 输出与验收

`app.py`、`scripts/replay.py`、`telemetry/event_log.py`、回放 manifest、集成测试与最小端到端操作说明。

- [ ] 原速、倍速、逐帧回放的逻辑事件及原因一致，耗时性能不在倍速回放上冒充实时结果。
- [ ] 输入源切换清所有轨迹/候选/队列，不把上一条录制的数据接到新窗口。
- [ ] 未加载模型、质量不足、非 owner、错误模式均可在 UI 解释。
- [ ] 实时双向翻页可完成；一次动作一次事件、自然动作的实际拒绝/误触、失跟/停止均有完整证据。没有意图头时不要求所有视觉相同的自然动作必定拒绝，必须报告限制、可用率和真实错误，而非只选成功片段。

失败必须定位到感知、标签、特征、模型、事件或后端层，再回相应任务修复。T24 在此基础上做故障与性能验收。

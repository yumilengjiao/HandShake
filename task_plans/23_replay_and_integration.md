## 目标

建立同一输入可复现的“观测→特征→模型→事件→通用命令→后端→UI/日志”链路。先 mock/dry-run 后受控 live；后续音乐/光标接入时复用该入口，不复制流程。

## 实施步骤

1. 应用控制器负责输入源、轨迹/特征状态、predictor、interaction engine、mapper、dispatcher、UI snapshot 和 telemetry 的生命周期；各模块共享同一版本上下文。
2. ReplayClock 按原录制相对时间驱动保持、冷却、过期和失跟；倍速/逐帧只影响观看速度，不改变逻辑时间。无手/无预测时仍推进时钟并调用健康检查。
3. 实时新鲜度使用当前单调时间；回放的“源年龄”使用录制/模拟时间，不能把相对时间和当前 wall clock 相减。历史回放后端固定 mock/dry-run，不连真实桌面。
4. 录制模型包、特征 schema、配置、数据与代码哈希；输出预测摘要、状态转移、GestureEvent、ActionCommand、ActionResult 和时间分解。不能只保存最终“成功/失败”文字。
5. 建固定 regression fixtures：正常左右挥动、保持/释放、自然挥手、无手、遮挡、多人冲突、失焦、乱序预测。无授权原视频时用骨架/合成输入与脱敏元数据。
6. 同一模型/配置/fixture 重复跑事件列表一致；对比 MLP/TCN 保留同一后处理。更改门限或特征时输出事件差异而非覆盖旧日志。
7. 集成分三步退出：A 合成预测贯通 UI/mock；B 真实关键点回放＋自训模型 dry-run；C 在 T17/T18/T19 局部安全检查通过后，受控 live 完成有页码的脚本。

## 输出与验收

`app.py`、`scripts/replay.py`、`telemetry/event_log.py`、回放 manifest、集成测试与最小端到端操作说明。

- [ ] 原速、倍速、逐帧回放的逻辑事件及原因一致，耗时性能不在倍速回放上冒充实时结果。
- [ ] 输入源切换清所有轨迹/候选/队列，不把上一条录制的数据接到新窗口。
- [ ] 未加载模型、质量不足、非 owner、错误模式均可在 UI 解释。
- [ ] 实时双向翻页可完成；一次动作一次事件、自然动作拒绝、失跟/停止链路有完整证据。

失败必须定位到感知、标签、特征、模型、事件或后端层，再回相应任务修复。T24 在此基础上做故障与性能验收。

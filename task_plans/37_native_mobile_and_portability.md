总约束见 [任务导航](README.md) 与 [原生架构](../docs/native_architecture.md)。手机需求在此正式落地，不以浏览器页面、桌面远程投屏或只完成 Android 代替全部移动目标。

## 目标与范围

按 T36 的已选路线，交付 Android 和 iOS/iPadOS 原生应用：在资产预置后可离线完成本机相机→关键点→特征→自训模型→安全状态机→本应用内翻页。Windows/macOS/Linux 的新增桌面目标复用同一平台验收模板，每个平台独立记录状态。

普通手机 App 不要求实现任意其他 App 的全局触控注入。外部应用控制仅在公开接口和用户授权允许时另列能力；远程手机控制电脑归 T38，不能替代本任务的本地识别要求。无设备/SDK/签名条件的平台标阻塞或待验证，不虚标整个任务完成。

## 实施步骤

1. 按平台实现 T03/T04 输入与感知适配，区分前后摄像头、YUV/BGRA/RGB、旋转/镜像、回调时间与曝光时间。记录感知资产和 SDK 版本，同帧多手处理、无手/未处理/失败保持统一语义。
2. 按 T36 路线复用或移植公共特征/状态核心。以 T11 Python 为参考：同一 golden 观测得到一致特征/掩码/ready/重置，测试因果性、时间抖动、长间隔、换轨迹与缺失；移植实现不能各自增加门限或修补语义。
3. 从 T16 正式模型包导出所选移动运行时模型，核对算子、shape、因果填充、归一化、类表和可选头。分别测 float32 与实际部署精度的 logits 容差、类别、校准、拒识及事件结果；量化只能用授权训练/验证资料，不能用最终测试集校准。
4. 移动壳实现触控、横竖屏、系统字体缩放、相机权限、模型加载/损坏提示、启用/禁用和停止。本地识别路径不请求网络，不把安装完整 PyTorch/Python 训练环境作为手机用户前提。
5. 实现本应用内受控演示目标，经同一状态机与调度器执行，返回应用确认；标明 application-local，不将其描述为外部 PPT 已支持。平台权限与 capabilities 改变立即停用，拒绝未知动作和目标。
6. 覆盖前后台、锁屏、来电/相机中断、权限撤销、进程重建、旋转与相机切换。恢复只预览，清 stream/epoch 与历史，不自动 live；不假设后台相机或退出回调可靠。保持独立健康/停止机制，持有类动作无法安全释放则禁用。
7. 每个平台按 T23/T24 的既有方案复跑回放、故障与实机闭环，记录延迟 p50/p95、有效 Hz、内存、电量/温升与至少 30 分钟稳定性。低端机不能只测启动；手机摄像头/帧率差异需补跨设备验证数据并遵守既有用户划分，不能拿桌面精度当移动端结果。
8. 按 T29 规则生成分平台安装/测试包及说明：OS/ABI、最低版本、工具链、许可证、模型哈希、签名/权限、离线资产、升级/卸载。Android 与 Apple 目标分开记录安装证据；不把模拟器通过或构建通过视为真机相机和安全通过。

## 交付与验收

产物为实际原生子工程、平台适配器、便携模型包、golden fixtures、跨实现一致性报告、每平台安全/性能记录与安装说明。实际路径由 T36 冻结，不先创建一堆空工程。

- [ ] Android 至少一台真机断网完成本机识别与应用内翻页；iOS/iPadOS 至少一台真机独立完成同项；未测试的手机/平板形态不继承兼容声明。
- [ ] 操作确由自训模型驱动，不是 MediaPipe 预置类别或按钮伪装；失败、无模型、无相机状态可解释。
- [ ] 特征、窗口、logits、事件与参考实现一致性有证据；不同感知 SDK 的差异另做实机评估。
- [ ] 生命周期中止/恢复、停止、旧结果拒绝与能力降级实测通过；电量/热降频不导致历史动作积压执行。
- [ ] 各平台安装、相机、本地推理、应用内/外部控制分别有结论，缺平台条件时保留未完成项。
- [ ] 平台发布前复用 T24 安全与 T29 发布检查，新模型/转换产物按 T28 流程验证冻结；不要求把 T24/T29 反设为本任务启动前置。

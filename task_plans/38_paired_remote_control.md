## 目标

手机原生 App 使用本机相机与识别核心，将标准动作命令送到已配对电脑 Agent，由目标设备本地调度器执行。首版只验证局域网、一台手机与一台电脑、翻页能力，不开放互联网远程控制、任意脚本或通用触摸注入。

## 实施步骤

1. 明确手机（输入/识别端）和电脑（执行端）的身份、目标应用、允许能力与操作范围；电脑上的服务可以复用桌面核心，不强制另写独立业务实现。
2. 实现双方可见的配对/确认、加密认证连接、凭据安全存储/撤销与会话租约。不可通过仅知道 IP 或扫描公开二维码就无限授权；首次配对验证对端，避免中间人或未授权客户端。没有网络时本机模式继续可用。
3. 设计版本化消息、大小/频率限制、command/event ID、序号、会话代际、目标和能力白名单；执行端不信任客户端已做安全检查，收到命令仍复核授权、租约、目标、停止位和新鲜度。外部客户端不能直接写 owner/epoch 或调用任意 shell。
4. 不直接比较设备之间的 monotonic 时间。保留源时间和本地接收时间，定义延迟/时钟偏差不确定度上界、漂移校验与拒绝策略；旧数据不能靠重新写接收时间或续租变新鲜。协议必须用可测的延迟/乱序案例证明 TTL 判定，不只画时序图。
5. 目标 Agent 的本地 watchdog 在断连、无更新、租约过期或停止时禁新提交、清队列并释放；不等待手机关闭回调。双端提供手动停止，目标电脑的独立停止优先于远程指令。
6. 重连更换会话/stream，失效旧 epoch，重新人工启用/唤醒；不补执行缓存动作。翻页等非幂等命令不因丢回执自动重试，不确定结果明确显示；连续/持有类控制先不启用。
7. 用合成网络故障验证丢包、延迟、重复、乱序、重放、断连、后台锁屏、权限撤销、目标切换、Agent 异常和晚到回执。敏感凭据与视频不进入日志，默认不传原视频。

## 交付与验收

产物为配对协议、原生端网络适配器、目标 Agent 接入层、威胁/权限说明、故障测试与双端安装/撤销指南。网络库和凭据存储方案在实施时按平台验证，不在此虚构版本。

- [ ] 一组实测手机/电脑可配对、控制明确目标并撤销授权；错误客户端/过期凭据/重放被拒绝。
- [ ] 手机杀进程、锁屏和网络中断时，目标独立停止有延迟/释放证据；重连无旧动作和自动 live。
- [ ] 两端时钟偏差、队列积压、延迟/乱序超预算不被误判为新鲜命令。
- [ ] 接收、注入、应用确认分层显示；丢失回执不产生重复翻页。
- [ ] 更新平台矩阵，仅公布实际配对组合；按 T24/T29 规则复核安全与交付，不继承其他组合的兼容声明。

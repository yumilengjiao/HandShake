## 目标与输入输出

输入为 T01 实测相机与 T02 配置；输出为带来源时间/变换元数据的标准 FramePacket。桌面先实现，Android/iOS 在 T37 复用协议与验收；CameraSource 不暴露 OpenCV 对象给核心，不假设所有平台都按设备索引读取。实时优先新鲜数据，录制必须暴露丢帧；请求帧率不等于实际达到。

## 实施步骤

1. 在 `capture/` 包装设备打开、读取、关闭和重连；首版可请求 640×480、30 FPS 作为探测起点，启动时读取并记录实际分辨率与实际采集频率。
2. 帧读取完成时记录 `monotonic_ns()` 并递增 frame_id；若设备无可信曝光时间，明确该时间近似为软件获得帧的时刻，不宣称是曝光起点。检查相机驱动/解码缓冲：刚 read 到的帧也可能早已曝光，最新帧槽不能单独证明端到端新鲜。记录后端缓冲行为，按支持能力调小缓冲并实测，不靠重写时间戳掩盖延迟。离线视频使用媒体时间轴；设备重连/换源新建 stream_id，不复用旧帧身份。
3. 推理端消费一个最新帧槽或小型有界队列；慢消费者允许跳帧并计数，不允许积压后补执行历史动作。采集和 UI 消费同一快照的只读副本，避免原图被覆盖。
4. 标准 FramePacket 使用 RGB8。桌面 OpenCV 常见 BGR、移动 YUV/BGRA 等均由平台适配器显式转换，记录源格式、裁剪、旋转、镜像与实际宽高；不得把所有设备假定为 BGR。先统一正立模型坐标，预览可镜像但不能暗改词元方向；横竖屏/前后摄像头切换按新输入流处理。
5. 对帧读取失败、空帧、重复/倒退时间戳、设备被占用发健康事件；连续失败时关闭 live、通知独立停止路径并释放后端。重连成功只恢复预览，不自动恢复控制权。
6. 区分设备/解码漏帧、实时消费者跳帧与录制写入丢帧；每个可记录的采集帧有处理状态，未送入感知不能标为“无手”。采集写盘线程阻塞时提示会话无效风险，不静默保存残缺数据；采集工具在 T06 落盘。

## 原生多端补充

- 相机授权、拒绝/撤销、系统中断、休眠、手机后台/锁屏通过生命周期适配器报告；停用和释放不依赖下一帧到达。恢复只预览，重新创建流/预热与授权。
- 移动 SDK 时间先保留来源时基再转换，不能将未知时基直接当 Python monotonic_ns；是否包含休眠时长写明。远程输入归 T38，不把收到网络帧的时间伪装采集时间。
- T37 每个平台另测旋转、前后摄像头、权限、帧格式与热降频；本任务的桌面探针不代表手机支持。

## 产物与验收

产物为 `capture/camera.py`、`capture/clock.py`、合成/文件输入源、`artifacts/reports/camera_probe.json` 的生成逻辑。

- [x] 连续headless采集约5分钟，报告实际采集/消费Hz、丢帧及队列最大长度；人工窗口预览另待验。
- [x] 人为放慢消费者时队列有界、跳过帧状态保留；源时间不被改写。探针报告软件read→消费者年龄，不宣称曝光年龄。
- [ ] 拔插、设备占用、窗口关闭、重复 stop 后设备可重新打开；重连不自动 live。
- [x] 颜色、宽高、镜像/旋转元数据可追踪；同流重复/倒退时间拒绝（合成/fake驱动/真实OpenCV文件测试）。

失败时先处理设备、权限与队列，不通过改写时间戳掩盖积压。T04 消费帧，T06 记录时间轴，T24 测量真实性能。

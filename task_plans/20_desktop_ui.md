## 目标与开发顺序

提供可独立启动的桌面控制面板。可先使用 mock 数据开发，不必等待模型训练；真实集成需要 T03/T04/T16/T17/T18，演示能力接 T19，音乐/光标接 T21/T22。UI 框架在目标机器比较启动、图像刷新、许可和打包后固定一种，不在方案中虚构已兼容版本。

## 必做界面

| 区域 | 功能与验收点 |

| 预览 | 相机画面/关键点、镜像提示、实际 FPS、无手/相机失败状态 |

| 设置 | 相机选择、首选手/镜像、参数档案入口；危险或热切换参数通过控制器验证 |

## 实施步骤

1. 按三块布局制作静态草图：左预览，中状态，右控制/最近事件。停止按钮始终可见且可键盘操作，颜色加文字。另实现经平台许可的独立停止键/目标应用停止通道，在演示窗口前台和 UI 绘制阻塞时实测；仅窗口内快捷键不算全局紧急停止，能力缺失需在 T01 限制 live 场景。
2. 应用控制器统一管理 start/enable/disable/stop/change_mode/load_model；UI 只发意图，不直接调用后端或改 state machine 字段。
3. 采集、感知和推理在工作执行单元，UI 线程消费只读快照。通知节流、队列有界；绘制变慢不积压控制帧，停止接收和健康监控不放在 UI 事件循环里。视图镜像只改显示与叠加坐标，不偷偷改变模型输入、词元含义或用户档案；改推理坐标策略必须重新校验 schema/模型。
4. 首次启动 dry-run。选择 live 时展示具体受支持目标能力和当前状态，使用者明确启用后仍需唤醒 owner；不能一打开窗口就控制桌面。
5. 模型加载失败、相机占用、后端不支持、焦点变化、过期帧、失跟显示具体原因和恢复步骤；普通错误不得关闭停止路径。
6. UI close 先禁新命令、清理队列/按下状态、停止 worker、释放相机再退出。模拟模型卡住时 UI 和停止仍可响应，不在 stop handler 无限 join。
7. P1 调试页可增加 top-3、意图/阶段、质量/确认进度、延迟 p50/p95 和回放；基础页不因没有这些研究头而缺失。

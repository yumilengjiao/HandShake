## 目标与开发顺序

提供无需浏览器的可安装桌面控制面板。T02 后可以先画草图、定义快照和做 mock；T36 的桌面路线决策是正式 UI 实现/框架冻结前置，不等待 T37 手机完整实现。真实集成需要 T03/T04/T16/T17/T18，演示能力接 T19，音乐/光标接 T21/T22。

UI、视图控制器和核心分离。用 T36 选定的一条技术路线，不同时维护多套候选框架；共享组件按实际可复用范围使用，跨语言 UI 经版本化接口接核心，不复制特征、推理与状态机。

## 必做界面

| 区域 | 功能与验收点 |
| --- | --- |
| 预览 | 相机画面/关键点、镜像与旋转提示、实际 FPS、无手/相机失败状态 |
| 模型与交互 | 模型版本、预测类别、track/owner、ready、当前状态及最近拒绝原因 |
| 控制 | 启动预览、人工启用、普通禁用、醒目的紧急停止；dry-run/live 显式可见 |
| 模式/目标 | 演示/音乐/光标、明确目标应用；未实现能力禁用并说明原因 |
| 事件 | 最近事件与执行结果，区分拟执行、已注入、应用确认 |
| 设置 | 相机、镜像、参数档案、权限状态；热切换经控制器验证 |
| 平台能力 | 显示应用内/外部控制差别，不将“可安装”显示成“能控制所有软件” |

## 实施步骤

1. 制作桌面布局并考虑窄屏、系统字体缩放、高 DPI、键盘和可选触控。停止按钮始终可见，颜色加文字；同时验证宿主允许的独立停止键/通道在演示软件前台和 UI 卡顿时可用。窗口内快捷键不算全局停止。
2. 应用控制器统一管理 start/enable/disable/stop/change_mode/load_model；UI 只发受控意图、接只读快照，不直接执行系统操作或改状态机字段。相机/权限由平台适配层持有，视图只发请求与展示结果。
3. 相机、感知、推理与写盘不阻塞绘制；通知节流、队列有界，健康与停止路径不放在 UI 事件循环里。采用 IPC 时验证核心失联、UI 崩溃和消息过期；不能只靠销毁窗口释放资源。
4. 预览镜像只改显示与叠加坐标，模型坐标策略按 T05 固定。切相机/方向变换时记录元数据并使旧 stream/epoch 失效，重新预热与授权，禁止沿用历史候选。
5. 首次启动 dry-run，用户选择明确目标后才允许启用，仍需唤醒 owner。模型失败、相机占用、权限撤销、焦点/目标变化、过期与失跟显示具体恢复方法，不显示虚假成功。
6. 正常关闭先禁新命令、清队列与按下状态、停止 worker、释放相机；停止 handler 不无限 join。桌面普通失焦不一概停机（演示软件需要前台），由目标策略判断；系统休眠、会话锁定和权限丢失默认挂起，恢复不自动 live。
7. 为 T37 交付与布局无关的视图状态和指令规范。手机壳需另验触控、前后摄像头、横竖屏、后台/锁屏；桌面截图和模拟窄屏不算手机验收。P1 调试页可增加 top-3、质量、延迟及回放，不要求没有的模型头。

## 交付与验收

产物为 `frontend/` 下实际原生组件/视图控制器、状态契约、启动入口、桌面安装冒烟与截图；由 T36 决定具体语言/文件名，不强制 `ui/main_window.py`，也不创建 Web 页面替代原生入口。

- [ ] 无模型能预览并显示原因，无相机能进入回放/mock；UI/mock 独立验收不等最终模型。
- [ ] 基础页可完成预览、启用、唤醒、翻页和停用；T23 提供真实模型闭环证据。
- [ ] 切换模型/模式/输入清旧候选，能力不足明确禁用；模型与界面镜像不混淆。
- [ ] UI 卡顿、关闭/崩溃、模型阻塞、系统挂起均不破坏核心停止路径，T24 实测时延。
- [ ] 首桌面平台安装后无需浏览器，权限/高 DPI/键盘操作有证据；其他平台保留待验证。

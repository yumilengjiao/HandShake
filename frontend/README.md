# frontend：原生桌面与移动交互界面（后续实施）

> 当前采用原生多端目标，替代此前 Web 约定。只有职责包和占位说明，没有可启动 UI；本次只改文档，具体技术路线由 T36 验证。

## 主责与任务

- **B 主责**；A 协助模型输出、指标展示与数据标注需求。
- 核心任务：[T36 原生选型](../task_plans/36_native_platform_foundation.md) → [T20 原生桌面界面](../task_plans/20_desktop_ui.md)；[T37 手机本地运行](../task_plans/37_native_mobile_and_portability.md) 后续交付，T38 可选配对控制。
- 关联 T06 采集/标注辅助、T21/T22 媒体/光标界面、T23 集成与 T27 个性化向导。

## 本目录负责什么

- 摄像头与关键点预览、镜像提示、实际帧率。
- 模型版本、预测类别、控制者、ready、状态与拒绝原因。
- 预览、启用、禁用、紧急停止以及明确可见的 dry-run/live 状态。
- 演示/音乐/光标模式选择，未实现能力禁用并说明原因。
- 最近命令的拟执行/注入/响应结果。
- 相机设置、用户校准向导、采集与标注辅助视图。

后续按 views/components/controllers 等职责划分，具体语言与原生子工程路径由 T36 冻结，不预建多套框架。桌面验证高 DPI/键盘/安装；手机另验证触控、横竖屏、前后摄像头、权限、后台/锁屏和本地离线识别。共享视图契约不代表所有平台可直接运行同一 Python UI。

## 输入输出与边界

- 从本机核心消费只读快照，经版本化接口发送用户指令；Python 可直接调用，不同语言经 T36 确定的受控 IPC/FFI。网络只用于 T38 可选跨设备模式。
- 界面不直接执行鼠标、键盘、媒体命令；相机/权限请求交平台适配器处理，UI 展示授权结果。
- 不在 UI 重新实现特征、推理和事件状态机；手机本地核心的移植与一致性测试归 T37。
- UI 控制器只做输入校验、消息转发及视图协调；整体生命周期与执行状态由后端应用控制器拥有。
- 相机/推理/写盘不能阻塞绘制。独立停止接收和安全释放属于后端，不能只靠 UI 窗口内快捷键。
- 显示镜像仅影响画面及叠加坐标，不偷偷改变模型坐标或手势标签。
